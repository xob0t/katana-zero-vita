# Batch A: enemies and enemy AI (PC 2.2 YYC vs Android 1.1.10 2.3 YYC)

Method: per-line token view (`tools/show.py`), then raw code on both sides for every claim. Scratch helpers in
`scratch_A/`: `pcann.py` (annotated PC x86 by GML line: var ids, doubles, builtin slots), `aseg.py` (Android
annotate.py output filtered by GML line), `brief.sh`, `wvar.py` (lines that touch a variable), `wnum.py`,
`callcount.py` (per-function call/number set comparison). "L" numbers are GML source lines; Android is usually +1.
`fr` = `global.fr` (time scale), the same on both sides wherever it appears below.

## 2. Platform-only / non-gameplay differences seen
- `obj_flashlightmaster` Create: PC L17 0xe35d57 `simple = 0`, Android L18 0x3f2fb98 `simple = 1` → Other_12 uses 1 light at offset 80 instead of 3 lights at offset 10 (performance simplification of flashlight lights). The effect on any light-based detection was not verified (I found no detection use).
- `obj_ceiling_turret` Step L32 0x13fd6f5 / L33 0x36b302c and `obj_floor_turret` Step L110 0x13e4158 / L111 0x3f552e4: bullet `bb.parent = -1` on PC (the 2.2 `self` constant) vs `-4` (noone) on Android. obj_bullet uses `parent` only for reflect bookkeeping (`instance_exists(parent)`, `parent.shoot_timer`, `hit == parent`). On PC, `-1` refers to the bullet itself, so the turret was never touched there either. I expect no gameplay effect.
- obj_bullet Step: spark/particle `bb.parent` set to `id` (L48) or `-4` (L105, L146) on Android where PC has `-1` (cosmetic particles).
- `obj_drone` Create L26 0x3cdcdc4: Android writes `sec_attack_timer = 5`, but no drone code reads it (dead store). Drone Other_10 has 4 Android-only `show_debug_message` calls.
- `obj_enemy`: `player_height_aim_offset = 0` (AI_init L197 0x1512d24) is never read anywhere (dead). AI_init L141/142: Android `hairNb` + `asset_get_index` hair selection (hair sprites).
- `obj_smokecloud` Create reads `global.smokeScale` (Android opto setting, default 1). `obj_drone`/`obj_wall_cam` `static` → `obStatic` (rename, since `static` is a 2.3 keyword).
- `obj_enemy_slash`, `enemy_hurt`: Android-only `show_debug_message` calls.

## 3. Inspected and identical / noise only
- `AI_init` other values: aim_radius (700 deterministic / `random(80)+random(80)+600+100`), personal_space 12 / `random(8)+8`, smoke_radius 50, run_speed 8.25 / `random(1)+7.75`, attack_spd 7, die_sound, replacement_object_override −4, the first_attack_timer stage ramp (+10 in room_factory_0 / +9 otherwise in stage 1, +4 in stages 2/3/5; PC room 6 = Android room 7 = room_factory_0), jump/hsp/roll constants, gun_y −36: identical.
- `obj_enemy*` Step `shoot_timer = 7 + round(6)` (PC, constant RValue at 0x1e1d318 = 6) vs `13` (Android) and `5 + round(30)` vs `35` (machinegun/sci/shieldcop/shotgun): identical (Android constant-folded).
- Enemy Step gates: first_attack_timer `<= 0`, melee range 78 px, `whip_timer -= 1*fr` decrement, `aim_radius`/`AI_line_of_sight(…,80)` checks: same constants.
- `obj_enemy_cop/sci/shotgun_Other_24` "Android-only 42/44/13/12": arm/gun offsets are int operands on PC (`-42 + arm_yoffset`, `-13 * dir`, `12 * dir`); int vs double.
- `obj_enemy_grunt_Other_16` 420, `obj_enemy_sci_Create_0` 445, `obj_enemy_shotgun_Create_0` 371, all `*_Create/Other_23/25` 3-4 digit numbers: PC sprite indices (spr_prisongrunt_fall, spr_sci_stairfall, spr_shotgun_stairfall…). Android builds them from a base ref + offset (`0x5f1|2` = 1523 = same sprite).
- `*_Step` PC-only 512 / 262144 / 805306368 / 1073741824 / 134217728: float32 lengthdir lengths (4.0f, 9.0f, 25.0f…) misread as double high words. Android passes the same floats (checked at enemy L75 and machinegun L86/L130).
- `obj_bullet_Step_0` PC 90/270 at L214: Android has them as movw/movt (0x40568000 / 0x4070e000). 266.666… is a rounding difference only.
- `obj_bullet_Other_10` 5 vs 4: `repeat(5 * particle_scaler)` on both sides.
- `obj_enemy_Step_0` PC 63/64 vs Android 64/65: room indices (room_mansion_2_2, room_mansion_3). `obj_grenade_shrapnel_Step_0` 27 vs 28: room_club_4_2. `obj_throwable_Destroy_0` 38 vs 39: room_prison_3_return. `obj_aidoor_Step_0` 51 vs 1299: spr_player_enterdoor.
- `Script_AI_physics` 20: `clamp(hsp, -20, 20)` on both (PC constant RValues 0x1cabf90/0x1cabfa0 = ∓20). `*0.25` / `*0.5` vs `/4` / `/2`: x86 division folding.
- `Script_ai_check_stairdoor`: `array_length_1d(waypoint) >= 2` (PC) vs inlined array length `>= 2` (Android).
- `Script_turret_aim` 0.4: present on both (Android movw/movt).
- `obj_enemycorpse_Step_0` 65/85: present on both (PC as immediates).
- `obj_enemybike_Step_0` clamp ±7 (PC constant RValues 0x1e2e758/0x1e2e768) vs inline 7; `obj_enemybike_bully_Other_12` 130 on both.
- `obj_enemy_Create_0` 14: `event_user(14)` on both.
- `*_Other_24` instance_create 1 vs 2 calls, ceiling_laser begin_animation 1 vs 2, ceiling_laser_bullets momentum_add 3 vs 2: the Android compiler duplicated or merged one call site across a branch. Argument values were not checked one by one; these are cosmetic objects/particles.
- `F:clamp` / `F:instance_exists` / `F:round` call-count differences: Android calls the YYGML_clamp/round builtins directly, plus 2.3 `instance_exists` guards.
- Drone, officer, officer_gaming, prisonguard, ceiling/floor turret, lasers (`obj_ceiling_laser*`, `obj_club_laser*`, `draw_laser*`), heli (other than #13), `obj_smokecloud`, `obj_throwable*`, `obj_stealthmaster`: the per-function number/call comparison shows only asset indices, float32 noise, debug calls and the items above. I did not find a timing/speed difference (I did not read them line by line).
- `AI_hearing`, `AI_aim`, `AI_see_player`, `AI_line_of_sight`, `AI_move_aimer`, `ai_aim_overlap`, `ai_idle_*`, `ai_open_door`, `ai_set_gunpoint`, `ai_set_hair` (205/195 = sprite indices): no number or call differences other than noise.
